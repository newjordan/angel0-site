What's new

Built different, on purpose.

Most agent tools bolt a model onto a REPL. angel0 starts from a different premise: the harness itself — routing, sandboxing, memory, verification, self-knowledge — is the product.

🛡️

Sandboxing as a first-class citizen

Every shell tool spawn is re-execed through a tiny dedicated angel-sandbox sibling binary with an explicit execution contract — not a shell escape afterthought. Workspace confinement is lexical and enforced at the path layer.

angel-sandbox · --sandbox-exec
🪞

A live self-model

The cockpit generates a map of its own source from the live tree every turn — module purposes, symbol outlines, build/test contracts — injected into its own context. It can reason about itself without a static, drifting ARCHITECTURE.md.

self_map · /self loop
📡

Telemetry that changes behavior

An experience ledger records every turn — hops, tokens, latency, cache-hit ratios — and the findings feed back into route calibration: cheapest-adequate model selection, spin-breaker tuning, hop budgets. Measurement closes the loop.

ledger.jsonl · calibration
🖥️

The terminal is the whole surface

No browser tab, no Electron. Ratatui renders the full cockpit — model controls, thinking budgets, world visuals (Scryglass, miniviz, image viewer) — inside the ordinary terminal, detached on demand for lean comp mode.

ratatui · zero-DOM
🤖

Agent-of-agents native

A fleet of OpenAI-compatible routes — local LAN seats, tailnet boxes, frontier APIs — is a first-class routing layer. Delegate, fan out panels, quorum-check answers, or drive one lane yourself; a practice floor keeps the cockpit useful with zero credentials.

clubs · spawn · delegate
🧾

Machine-facing by contract

angel --task-json is a stable RL/competition entrypoint: exactly one result object on stdout, progress on stderr, explicit task/run IDs, hop and deadline limits, auditable rollout capture. The same binary humans drive is the one benchmarks grade.

--task-json · one result object
🌍

Worlds, not dashboards

Progress is spatial: a persistent realm with travel, arrival, and landmarks — a 3D realm, Scryglass scenes, a first-person miniviz — where verification and activity are visible as motion. The literal operation always leads the metaphor.

realm · miniviz · scryglass
🦀

Ship-speed Rust, no runtime

~440k lines of Rust, zero async runtime — blocking HTTP with rustls, thin-LTO release profile, a stripped single binary. The performance story is engineering discipline: codegen-units=1, symbol strip, a feature-gated video path that keeps default spawns light.

no async · thin LTO · 1 binary
🧱

Safe self-modification rails

Because it can see its own source, it can improve it — under layered rails: workspace confinement, a hard gate on self-edits, and an always-available rollback path. The cockpit must never be able to brick itself.

four rails · hard gate

Architecture

One binary, many surfaces.

Everything below ships in a single release build: angel (the cockpit) plus its tiny sibling angel-sandbox for cheap, confined tool spawns.

01 · drive

Human in the cockpit

Ratatui TUI: conversation, model/thinking controls, tool transcripts, slash surface, world panes. Lean comp mode detaches visuals for maximal speed while every surface stays callable on demand.

02 · route

Club routing layer

OpenAI-compatible routes across LAN seats, tailnet fleet, and frontier APIs. Calibration data (hops-to-answer, input tokens per route) informs which club drives which class of task.

03 · act

Sandboxed tool plane

File edits, shell, code search, research tools — each spawn re-execed through angel-sandbox with explicit scope grants (read-only, write-paths). A denial is a permission failure, never a silent zero score.

04 · verify

Evidence-gated outcomes

Claims require verifier output. The competition runner grades read-only, from a fresh workspace, against resumable attempt ledgers — the cockpit can't grade its own homework.

05 · learn

Experience ledger + self-model

Every turn lands in the ledger; findings feed route calibration and breaker tuning. The self-model regenerates from the live tree, so the agent's map of itself can never go stale.
